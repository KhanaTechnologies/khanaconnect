# Backend audit, 8 Nov 2026

Scope: the khanaconnect API: the global auth gate, the 37 route files, tenant isolation, the Meta / WhatsApp / PayFast / email integrations, background jobs, error handling and dependencies. The dashboard (api-service-nexus) and client storefronts were not audited.

## Fixed in this change

| # | Severity | What | Where |
|---|---|---|---|
| 1 | **High** | **Email search could read other businesses' mail.** The `field` option was used as a database key, so `field=clientID` replaced the tenant filter with a match-everything search. It now only accepts subject / from / to / body / html. | `routes/emailRouter.js` (`GET /email/search`) |
| 2 | Medium | **Search text went straight into regex queries.** A stray `(` caused a 500, and a crafted pattern could tie up the database. All five searches now escape the text and cap it at 200 characters. | `helpers/escapeRegex.js`, `routes/emailRouter.js`, `routes/campaigns.js` (×2), `routes/votingCampaigns.js` |
| 3 | Hardening | JWT verification is pinned to HS256, the only algorithm the API signs with. | `helpers/jwtSecret.js` |
| 4 | Noise | **Error emails only for real server errors.** Bad JSON, blocked CORS origins and deliberate 4xx errors used to email you as incidents, and blocked CORS requests came back as 500s. Now 4xx errors are answered quietly and CORS rejections return 403. | `helpers/failureEmail.js`, `app.js` |
| 5 | Upkeep | **Removed 7 unused packages** (both Mailchimp packages, `octokit`, `express-jwt`, `google-ads-api`, `googleapis`), added `express-unless` (it was used but only arrived through `express-jwt`), and moved `nodemon` to devDependencies. Production audit warnings dropped from 7 to 4 moderate. The remaining 4 sit in build tooling inside `@google-analytics/data`, and none are high or critical. | `package.json`, `package-lock.json` |
| 6 | Upkeep | Deleted an unused error handler that sent raw error objects to the browser. | `helpers/error-handler.js` |

Tests: 16 new offline checks pass (escaping, error-email rules, JWT, route loading, the search allow-list). The earlier WhatsApp suites still pass (13 and 7), and every tracked `.js` file passes `node --check`.

## Recommended next (not changed)

1. **High: the PayFast passphrase reaches the browser.** Storefronts sign PayFast checkouts in the browser, so `GET /client/:id` hands `merchant_key` and `passphrase` to any token for that business, including the storefront token that ships in public site code. Add a server endpoint that builds and signs the PayFast form, move storefronts to it, then strip `passphrase` from `stripClientSecrets`. Order ITNs are still protected (PayFast validate check, merchant match, amount match), so this is about forged checkout requests, not free orders.
2. **Medium: the delivery price comes from the browser.** `POST /orders` trusts `deliveryPrice` from the request, so a customer could set delivery to R0. Work it out on the server from the store's delivery options.
3. **Low:** product images sent over WhatsApp are fetched from whatever URL the store saved. Only allow public https hosts.
4. **Low:** Socket.IO is started but nothing sends on it and the dashboard never connects. Remove it (and the `socket.io` package) unless live updates are planned.
5. **Low:** list endpoints accept any `sortBy` field (`campaigns.js`, `preorderPledges.js`). Add an allow-list.
6. **Upkeep:** 201 uploaded files (64 MB) are committed under `public/uploads`. Render's disk is wiped on every deploy anyway, so uploads belong in object storage (the code already has a GitHub-upload path).
7. **Upkeep:** there is no `npm test` script. Add one and keep offline tests like these in the repo.

## Checked and fine

- **Global auth gate** (`helpers/jwt.js`): only genuinely public paths are exempt.
- **Token types:** customer, B2B and storefront tokens are kept out of dashboard routes (`helpers/teamAuth.js`, `helpers/dashboardAuth.js`).
- **Tenant checks:** lookups by ID filter by business.
- **Field-copy loops** use allow-lists.
- **Meta webhooks** check the HMAC signature against the raw body.
- **PayFast ITNs:**
  - orders are confirmed with PayFast and checked for amount and merchant;
  - credit top-ups also check the signature and refuse duplicates.
- **Order and booking payment callbacks** stay off unless enabled with a secret.
- **Request protections:** CORS allow-list, Helmet, rate limits, Mongo operator stripping, and body size limits.
- **Secrets:** none committed, and `.env` is ignored.
- **Public links:**
  - quote IDs use 64 random bits;
  - booking manage tokens are checked for their purpose and business.
- **Error replies:** 500s are generic and carry a reference.
- **Process safety:** crash handlers and graceful shutdown are in place.
