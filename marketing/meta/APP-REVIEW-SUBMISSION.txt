================================================================================
pages_show_list
================================================================================
How we use it:
KhanaConnect is a business management platform. Clients connect Meta so they can
manage Facebook Page ads, boost Page posts, and view Page-linked performance.
After Facebook Login we call /me/accounts to list Pages the person manages and
show that list so they can select the correct Page for their workspace.

Value: Clients who manage multiple Pages can choose the right one. Without this
permission they cannot connect a Page for ads or boosting.

Necessity: Required to verify Page management and power Page-based Meta Ads features.

Screencast: Meta Ads or Account Management → Connect Facebook → consent → Page
dropdown shows managed Pages → select Page → Save.

Agree: Yes — use only for listing/verifying managed Pages and related allowed uses.

================================================================================
pages_read_engagement
================================================================================
How we use it:
After a Page is selected, we read that Page’s feed/posts and engagement summaries
(likes/reactions, comments, shares) so the client can boost posts and see organic
post activity in Meta Ads → Posts / Boost posts.

Value: Clients boost existing organic posts and monitor Page engagement without
leaving the dashboard.

Necessity: Cannot list Page posts or engagement for Boost / Posts without this
permission. (Requires pages_show_list.)

Screencast: Connect → select Page → Boost posts → Facebook → posts load → open
Boost dialog (create as PAUSED). Also Meta Ads → Posts showing like/comment counts.

Agree: Yes — allowed usage only.

================================================================================
pages_read_user_content
================================================================================
How we use it:
Meta’s Page published_posts / posts edges require this permission (or Page Public
Content Access) to read content associated with the managed Page. We use it only
for Pages the client selects and manages, to list organic posts for Boost and the
Posts activity view alongside pages_read_engagement.

Value: Reliable Page post listing for boost and engagement UIs.

Necessity: Without it Graph returns (#10) on published_posts/posts even when
pages_read_engagement is present.

Screencast: Same as pages_read_engagement (Boost posts + Posts tab).

Agree: Yes — allowed usage only. Read-only for managed Pages.

================================================================================
pages_manage_posts
================================================================================
How we use it:
Clients publish organic posts to their selected Facebook Page from Meta Ads →
Publish (text, photo, carousel, video), optionally together with Instagram, or
on a schedule. We call Page photos/feed/videos with the Page access token.

Value: Create Page content from Khana without opening Facebook manually.

Necessity: Required to create Page posts on behalf of the managed Page.

Screencast: Meta Ads → Publish → Facebook (or both) → caption + media → Publish now.

Agree: Yes — allowed usage only for Pages the client manages and selects.

Necessity: Required for Facebook Login connection identity.

================================================================================
business_management
================================================================================
How we use it:
Primarily to resolve and use Meta Business Manager context for the client’s
connected Facebook Login: associate the correct Business with their selected
ad account (metaBusinessId), surface Setup checklist / Business Manager deep
links (billing, Business Settings), and keep ad workflows scoped to BM assets
the authenticated user is allowed to manage—not a disconnected personal-only
setup.

Catalog create/sync under the client’s business is a supported follow-on when
Catalog Terms and permissions allow; it is secondary to BM context for Setup
and ad-account operations.

Value: Clients see which Business / ad account their workspace is tied to and
run Meta ads from Khana against the correct BM assets.

Necessity: Without business_management we cannot reliably read Business Manager
association for the connected ad account or operate BM-scoped asset context in
Setup and related Marketing API flows.

Screencast: Meta Ads → Setup — Page + ad account connected, checklist / Business
Manager deep links (payment or Business Settings). Narrate BM context resolution.
(Catalog sync optional if working; not required for this clip.)

Agree: Yes — allowed usage only.

ads_read
================================================================================
How we use it:
We read ad account insights (spend, reach, clicks, impressions, campaign breakdowns)
and display them in Meta Ads → Insights with CSV/print export.

Value: Clients see delivery performance of Khana-created and Meta campaigns.

Necessity: Insights UI cannot function without ads_read.

Screencast: Meta Ads → Insights → charts/metrics → optional CSV export.
(Seed a paused or active campaign first if the account is empty.)

Agree: Yes — allowed usage only.

Clients create and manage Meta campaigns from Khana: boost Facebook/Instagram posts,

================================================================================
How we use it:
Clients (or Khana on their behalf) connect a WhatsApp Business Account via Cloud API

Value: Order/booking alerts and WhatsApp inbox on the business number.

API test calls: WABA subscribed_apps, message_templates, send message.

Agree: Yes — allowed usage only.

================================================================================
whatsapp_business_manage_events
================================================================================
How we use it:
For a WABA administered by the client, KhanaConnect links a Conversions dataset
(GET/POST /{WABA_ID}/dataset) and logs conversion events (LeadSubmitted, Purchase, etc.) to
Meta via POST /{DATASET_ID}/events with action_source=business_messaging and
messaging_channel=whatsapp, including ctwa_clid from Click-to-WhatsApp ad referrals.
Used for ads targeting, optimization, and reporting in Events Manager.
First inbound CTWA message also auto-sends LeadSubmitted when ctwa_clid is captured.

Value: Clients optimize Click-to-WhatsApp ads using real LeadSubmitted/Purchase outcomes.

Necessity: Cannot send WhatsApp messaging conversion events to Meta without it.

Screencast:
1. Account Management → WhatsApp → Advanced Cloud API (credentials saved).
2. Link Events Manager dataset.
3. Ensure a Click-to-WhatsApp conversation produced a ctwa_clid (or paste one).
4. Send test LeadSubmitted (and optionally Purchase) event.
5. Show success in Khana and/or Events Manager dataset activity.

Agree: Yes — only for logging events on WABAs for Meta ads targeting, optimization,
and reporting per allowed usage.
